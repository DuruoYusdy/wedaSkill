# 射频差分信号（AFE 相关）信号匹配技能

**功能说明：** AFE/ADC/DAC 模拟差分链路的幅度、共模、带宽、匹配及单双端转换分析。

主要内容：引脚别名与方向、电气兼容、拓扑决策、连接矩阵、SI/时序和检查项。先读取 [SPEC.md](SPEC.md) 的范围、规则与待补项，以及 [通用规则](../00-通用规则与模板修正.md)。本文是参考库草稿；不是某组器件已完成的匹配报告。

**覆盖范围：** AFE/ADC/DAC 模拟差分链路的幅度、共模、带宽、匹配及单双端转换分析。 不适用于仅凭接口名称直接落板、跨协议套线或缺少必选入口的实际匹配。

## 输入要求或入口条件（必选）

用户提供信息应包含：

- **器件 A 和器件 B**（多设备时为全部参与器件）的接口引脚定义：原始名称、功能、相对本器件的方向；有复用时给出本次模式。
- 工作场景、端点角色、设备数量与物理连接边界：一驱一 / 一驱二 / 一驱多，或本文明确定义的点到点、链式、总线、交换网络等拓扑。
- 可选：工作电压、电平标准、速率、线长、层叠、连接器、上电/掉电状态及性能目标；这些不是统一入口必填项。

**必选信息不全，先询问并等待补充，再分析实际连接。** 等待期间只整理资料与缺口，不输出候选连线。可选电气信息缺失时可做依据充分的逻辑匹配，但电平/SI 为 `UNKNOWN`，不能确认最终电气直连。编写参考文档时可继续维护草稿，不要求虚构一组 A/B。

## 核心工作流（必选）

### 第一步：解析射频差分信号（AFE 相关）信号引脚（必选）

提取所有参与器件相关引脚，按功能、角色和模式标准化；先查确切型号/封装的 datasheet、勘误和 pin mux。网络名只生成候选。

#### 射频差分信号（AFE 相关）信号常见引脚命名变体（必选）

| 标准名/功能组 | 必须识别的候选别名 | 常见变体 | 功能/方向与限制 | 证据状态 |
| --- | --- | --- | --- | --- |
| ANALOG_IN | AIN+/AIN- | VIN_P/N, INP/INM, RX_P/N | 模拟接收输入，不能当 LVDS | 候选别名；须器件手册复核 |
| ANALOG_OUT | AOUT+/AOUT- | VOUT_P/N, IOUT_P/N, TX_P/N | 电压/电流输出先区分 | 候选别名；须器件手册复核 |
| COMMON_MODE | VCM | VOCM, VCMO | 可能是偏置输出或控制输入，功能非同义 | 候选别名；须器件手册复核 |
| CLOCK/LO | CLK+/CLK- | LO_P/N, RFCLK_P/N | 专用时钟/本振，单独接口规范 | 候选别名；须器件手册复核 |
| RF_PORT | RF_IN, RF_OUT | RFINP/M, RFOUTP/M | 名称仅候选，按具体 AFE 定义 | 候选别名；须器件手册复核 |

#### 引脚方向判断规则（必选）

按信号链确定驱动/接收端及电压型/电流型；VCM 与 VOCM 不能仅因名称相似相连。极性互换会改变模拟相位，不能默认允许。

- 使用已配置模式下的引脚功能表为准；I/O 是能力标记，不代表所有时刻都允许同时驱动。
- `n`、`#`、横线等是低有效命名线索，仍须核对；无此前缀不能推断高有效。
- 厂商对照表为可选。本稿不将某器件命名或 GPIO 编号推广为整个厂商惯例。

### 第二步：电平判断结论

#### 判断器件电平（按优先级）

1. 读取具体引脚功能、电气类型、所属 bank/IO 域与实际配置、供电；不能只读芯片核心 VCC。
2. 读取对应工作条件下的推荐范围、DC/AC Electrical Characteristics、输入容限、输出负载、掉电与钳位限制。
3. 用 Supply Voltage 与板上供电确认适用工作点和允许范围；可调供电范围不代表实际能同时兼容范围内全部电平。
4. 以协议/PHY 规范和参考设计复核；同一条件资料冲突时列明冲突，不能用优先级静默覆盖。缺关键依据记 `UNKNOWN`。

**本接口判据：** 比较差分摆幅/满量程、共模工作范围、输入阻抗与输出负载、频带、噪声和线性度；电流型输出另核对 compliance。不得套用 GPIO 的门限结论。 来源与实施细节见 [通用电气规则](../00-通用规则与模板修正.md) 和 [SPEC](SPEC.md)。

结论必须逐器件、逐信号方向记录：实际 IO 域/电气标准、门限或摆幅/共模、额定/掉电条件、资料位置、兼容性及是否需要中间功能。结论使用 `PASS / FAIL / UNKNOWN`；未分析为 `NOT_CHECKED`。

#### 电平转换方案选择（按优先级）

1. 原生幅度/共模/阻抗/带宽兼容时采用有依据的匹配与连接电路。
2. 按实际问题选择 balun、全差分放大器、匹配/衰减、耦合与偏置网络，计算噪声/损耗。
3. 电流/电压模式不兼容需相应模拟转换电路；禁止用数字电平转换器处理模拟 RF 差分信号。

任何候选方案都需核对 DIR/OE、供电顺序、输出释放、负载、延迟和本接口协议行为；未选型时只写功能节点，不能编造器件引脚号。

### 第三步：连接规则与场景判断匹配（必选）

#### 信号流向及连接规则

按信号链确定驱动/接收端及电压型/电流型；VCM 与 VOCM 不能仅因名称相似相连。极性互换会改变模拟相位，不能默认允许。

逐条执行 [SPEC 的 R-001 起各规则](SPEC.md#规则与要求)，规则包含适用条件与来源。以下是本接口的拓扑分支；“一驱”只是便于对照用户格式，不表示所有接口都有 Master/Slave。

**一驱一（SCN-001）**

一驱一：驱动器→所需匹配/耦合/偏置→接收器，保持极性与共模。

```text
Source -> verified analog matching/bias -> AFE1
```

**一驱二（SCN-002）**

一驱二：不得默认裸分叉；评估专用功分/分配放大器、插损、隔离及两端负载。

```text
Source -> specified splitter/amplifier -> AFE1 + AFE2
```

**一驱多（SCN-003）**

一驱多：建立有规格的分配网络，逐通道预算幅相、噪声和串扰；不同 AFE 负载不得按数字扇出处理。

```text
Source -> specified analog distribution network -> AFE1..AFEn
```

**接口详细链路示意（抽象功能例图）：**

```text
Analog source P/N --> matching / coupling / bias --> AFE AINP/AINM
Optional fan-out: source --> specified splitter/amplifier --> AFE1
                                                         --> AFE2
Digital JESD/LVDS link: separate from this analog path
```

- 一驱一：列出 A 与 B1 的全部目标信号；不存在的可选脚注明“不存在/不适用及依据”。
- 一驱二/一驱多：分别列出 B1、B2…Bn；共享网标识相同但每个端点单列。独立端口/链式逐段展开，不能只复制共享总线假设。

- 未确认电气条件时写“逻辑候选，电气 UNKNOWN”；建议不等同已写入 EDA，也不等同已观测原理图。

### 第五步：信号完整优化分析

使用频域 S 参数、回波/插损、幅相不平衡以及时域摆幅验证；噪声/SFDR/线性度、滤波器和时钟抖动依应用预算。普通数字转换器不适用。

按 [SPEC 的 SI-001](SPEC.md#信号完整优化分析) 记录输入、方法、限值来源、计算/仿真/实测和结果；缺资料的具体项目为 `UNKNOWN`。不得固定使用“Stub<20mm”“差长<5mm”“节点增加就降至固定百分比”或“一律添加固定阻容”等跨接口阈值。

## 输出格式

始终按以下顺序输出五部分：

1. **电平判断结论** — 每器件/电源域及每方向的兼容性、依据和未知项。
2. **信号匹配结论** — 逐场景连接矩阵，保留标准名与原始引脚名；说明哪些连、哪些禁止、哪些未定。
3. **连接示意图** — 本次实际拓扑 ASCII 图，展开所有中间功能和共享/独立关系。
4. **风险检查清单** — 下述通用与本接口分场景检查项的逐项证据/结果。
5. **补充建议** — 有条件的时序/SI/外围/转换方案、所需资料和下一步验证。

**分场景加检：**

- 一驱一：一驱一：驱动器→所需匹配/耦合/偏置→接收器，保持极性与共模。 检查双方功能、默认态和单链路电气/时序。
- 一驱二：一驱二：不得默认裸分叉；评估专用功分/分配放大器、插损、隔离及两端负载。 增查共享返回、片选/仲裁或第二独立端口的约束。
- 一驱多：一驱多：建立有规格的分配网络，逐通道预算幅相、噪声和串扰；不同 AFE 负载不得按数字扇出处理。 逐端点复核总负载、域/时钟、地址/路由或链顺序，不按数量套统一降速。

运行时给每项补上对象、方法、限值来源、证据、结果和未决项。结果只用 `PASS / FAIL / UNKNOWN / NOT_APPLICABLE / NOT_CHECKED`。入口不满足时只执行入口核查，其余记 `NOT_CHECKED` 并写原因；不能报告整体通过。
